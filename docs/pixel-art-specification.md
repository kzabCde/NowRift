# NowRift pixel-art production specification

The baseline audit is preserved in `pixel-asset-audit.md`. This document defines the integration contract used by the visual overhaul. Readiness describes whether an asset can be used by the engine, rather than claiming that procedural art has received extended hand-painting or human animation review.

## Pixels, camera and silhouettes

- World terrain remains 32×32 source pixels. Biome tile maps, navigation bounds and obstacle collision shapes remain authoritative.
- New modular character source frames are 48×48. All layers share a 26-column, four-direction atlas (1248×192). Rows are down, right, up and left. Left-facing source art may mirror authored right-facing art.
- Existing enemy frames remain 32×32 and bosses 64×64. Their established ten-frame grids and collision radii are preserved. Source resolution and world display scale are separate concerns; increasing a sprite's rendered height must not increase its collision radius implicitly.
- Main-hand equipment and interaction tools use a separate 32px atlas, with attachment points authored for each body. They are never baked into the body layer.
- Inventory cells remain 32×32, projectiles 16×16, and skill effects use 48×48 frames in compact 384×96 family atlases.
- Phaser uses nearest-neighbor sampling, integer source frames and rounded render positions. React previews use the same pixel atlases with `image-rendering: pixelated`. Responsive camera zoom does not resample or rewrite the source artwork.

The palette uses restrained green/teal shadows, warm cream edge highlights, desaturated leather and distinct metal/wood/cloth materials. Biomes retain their own established palettes. Fire uses warm orange/ivory, frost cyan/white, arcane blue/violet, nature green/gold and physical strikes pale metal. Essential warnings remain readable with reduced effects.

## Modular character atlas

| Track                            | Source columns | Playback           | Behavior             |
| -------------------------------- | -------------- | ------------------ | -------------------- |
| Idle                             | 0–3            | 6 FPS              | Loop                 |
| Walk / run                       | 4–9            | 10 / 13 FPS        | Loop                 |
| Melee / ranged                   | 10–13          | 16 / 14 FPS        | One-shot             |
| Casting                          | 14–17          | 12 FPS             | One-shot             |
| Hit / knockback                  | 18             | 10 FPS             | Interrupt            |
| Death                            | 19–21          | 9 FPS              | Terminal             |
| Respawn                          | 21,20,19,0     | 8 FPS              | Explicit restart     |
| Interact / mine / gather / craft | 22–25          | 8 / 10 / 7 / 9 FPS | Receipt/event driven |

Running, dash and other tracks do not grant gameplay abilities. They are available presentation tracks only when a supported game event supplies them. Mining, gathering and crafting share a synchronized body track while their tools and effects distinguish the actual action.

`game/presentation/animation.ts` is the central clock and frame contract. The mutable state machine avoids per-frame state allocation, ignores duplicate event tokens, holds one-shot actions against lower-priority locomotion requests, and permits damage/death interruption. Death remains terminal until a respawn event. Elapsed time comes from the existing scene/simulation clock; passing zero pauses it. No entity-specific browser timer schedules animation frames.

Animation priority is death → respawn → knockback → hit → supported dash → attacks/casts → interactions → run → walk → idle. Attack wind-up, impact and recovery are presentation phases. Actual combat collision and successful inventory/world transactions determine damage and resource awards; animation frames never authorize either.

## Asset registry and production workflow

`game/presentation/asset-index.ts` records every public PNG's source path, dimensions, byte count and SHA-256 content revision. It is generated by `scripts/generate-asset-index.mjs`; public branding/install icons are included along with gameplay art.

`game/presentation/assets.ts` turns that index into typed assets with texture keys, frame grids, category, scene bundle, anchor, scale, direction mapping, animation tracks, compatibility and audit status. Paths remain stable. The registry resolves both public paths and Phaser texture keys. Deprecated composite/legacy town character sheets are classified UNUSED and are not automatically queued; the original player fallback remains available.

`phaser/asset-preloader.ts` queues registry assets, avoids duplicate loader requests, and distinguishes full images/tilesets from sprite sheets. Scene bundles include only common effects/UI, the current biome and explicitly requested appearance layers. The whole character wardrobe is not loaded at initial application startup. Dynamic equipment loading uses the same registry and source grids as initial scene loading.

After any art generator adds or changes PNGs:

```sh
npm run assets:index
npm run assets:check
```

When releasing changed pixels at retained public paths, also advance `VERSION` in `public/sw.js` so installed clients discard the preceding art cache. The manifest revision validates content; it does not rename public URLs.

`assets:check` rejects stale revisions, missing/unregistered PNGs, invalid signatures, dimensions that cut partial frames, duplicate keys, animation frames outside a direction row and unresolved item/weapon references. The generated index uses the repository's Prettier formatting, so normal formatting does not make its integrity check fail.

The original CC0 generators are production sources, not a reason to claim unfinished placeholder assets as polished. Any missing human-authored refinements or unsupported art scope belongs in the final production backlog with exact required files and grids. Existing local save IDs and inventory ownership never depend on an art filename or cache revision.
