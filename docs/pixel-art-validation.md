# Pixel art and animation migration

This change extends the existing game rather than adding another combat or inventory implementation. It preserves three playable classes, six real equipment slots, four worlds/twenty campaign stages, the practice encounter, Haven, farming, crafting, progression, English/Thai, guest saves and checkpoint ownership. New art is original, locally generated pixel art with CC0 notices and editable sources. The supplied reference images were used for direction; no reference pixels or third-party sprite packs were copied.

The [pre-change inventory and audit](pixel-asset-audit.md) was written before implementation. The [production specification](pixel-art-specification.md) defines source sizes, pivots, direction rows, tracks and loading contracts. “Ready” in the asset registry means a valid integrated engine asset, not a claim that procedural artwork has received a professional hand-painting pass.

## Appearance and save compatibility

`resolveAppearance` is the single presentation resolver for React and Phaser. Each actor uses independently replaceable body, skin, face, hair, inner clothing, pants, back/cloak and applicable armor, gloves, headwear, boots, ring and necklace layers. Armor ownership also supplies matching pants/gloves; these are visual parts of the same owned item, not additional inventory slots. A helmet can cover hair. The wardrobe explains this and changes the underlying choice without unequipping gear.

Each 48px layer is a 1248×192 atlas: 26 columns × four direction rows. A shared scene clock selects the same frame for every visible part. Depth changes put the cloak and held weapon on the appropriate side when facing away. Hand anchors match the generator's anatomy. Weapons remain 32px independent sprites: canonical weapon frames 0–3; rare variants 6–9; epic/legendary variants 10–13; practice daggers/orb 4–5; interaction tools 14–17. Common/uncommon and epic/legendary share shape tiers, while rarity colors and enhancement effects retain their actual item values.

Customizations and checkpoint appearances are optional additive save fields; existing profile and checkpoint schema numbers remain unchanged. Old saves select the default appearance. New run snapshots freeze canonical equipment IDs, appearance choices and validated local layer references. Recovery therefore retains the original look and combat weapon after inventory changes. Appearance validation recomputes the canonical layer set instead of trusting imported URLs. Cosmetic commands do not alter stats, wallets, item ownership or reward calculations.

Crafting, enhancement, dismantling and world-action poses follow successful repository commits. Receipt UI shows positive deltas from the committed inventory. Failed writes grant neither items nor success animations. Expedition mining/gathering feedback waits for a checkpoint storage acknowledgment; pending harvests remain visible until that acknowledgment. Animation never awards damage, currency, experience or materials.

## Asset migration and reproducibility

- The baseline contained 92 public PNG files. The final manifest contains 354, including six branding/install PNGs and 348 game PNGs. The 262 additions are 252 modular character atlases, seven VFX atlases and three animated station atlases.
- Existing content IDs and live public paths are retained. The old flattened character/outfit PNGs remain marked `UNUSED` and are excluded from automatic scene queues. The original player sheet remains an explicit loading-error fallback.
- Biome enemy/boss sheets retain the established 32px/64px ten-frame API, and item icons retain the 32px atlas API. Tree/rock props and species previously sharing duplicate pixels now have distinct silhouettes. Biome collision footprints and the existing boss/AI patterns remain authoritative.
- All 348 game PNGs regenerate byte-for-byte using `npm run assets:generate` and the pinned optional Pillow dependency. Python is unnecessary at runtime, during `npm ci`, or for a production build. `assets:check` is part of the production prebuild.
- Initial scene loading includes common effects, the current world and the selected appearance only. The entire 252-sheet wardrobe is never eagerly decoded. Live wardrobe changes load missing selected layers without replacing the canvas.
- Service-worker cache `v15-pixel` retains the shell, starting Forest/Haven art, and warms visited world/appearance assets. Later biomes and wardrobe variants require an online first visit. Save data stays in IndexedDB; the art cache does not own progression.

### Performance observations

Measured in this managed Linux environment with Node 24.22.1, Chromium 156 and Phaser 4.2.1 Canvas2D. [Raw observations and alternating simulation runs](pixel-performance.json) preserve the values and scope.

| Measurement                        | Before   | After                   | Scope                                                                                               |
| ---------------------------------- | -------- | ----------------------- | --------------------------------------------------------------------------------------------------- |
| Early forest render FPS            | 60.13    | 60.25                   | Same ordinary production journey, 1280×900, three seconds of `requestAnimationFrame` sampling       |
| Early forest p95 frame interval    | 16.8 ms  | 16.7 ms                 | Same sample; not a crowded-fight benchmark                                                          |
| Simulation mean per frame          | 0.335 ms | 0.328 ms                | Median of three alternating 3,600-frame / 180-enemy runs against baseline `8969177` and this source |
| Simulation p95 frame time          | 0.435 ms | 0.415 ms                | Same Node runs; excludes rendering                                                                  |
| 150-enemy rendered desktop         | —        | 60.08 FPS / 16.8 ms p95 | Eight-second fixture at 1280×900                                                                    |
| 150-enemy rendered mobile viewport | —        | 58.54 FPS / 16.8 ms p95 | Eight-second fixture at 390×844 with 4× CPU throttle                                                |

These observations show no meaningful regression in the sampled workloads; the small simulation difference is not evidence of an optimization win. No paired pre-change 150-enemy rendered measurement was captured for this branch. Earlier release benchmarks are not substituted for one. Throttled desktop Chromium does not establish physical phone, Safari or Firefox performance. The full public PNG manifest totals 1,644,734 compressed bytes; selected appearance layers are decoded on demand.

The unchanged seeded survival bot completed the real encounter at 527.85 seconds, with 911 kills, 175 HP, level 23 and 2,749 gold. That is regression evidence for combat/RNG behavior, not human difficulty testing.
